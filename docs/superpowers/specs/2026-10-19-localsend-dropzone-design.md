# LocalSend Dropzone 设计

日期：2026-10-19
状态：待用户确认

## 为什么做

现在用 LocalSend 发文件，每次都要先从托盘或开始菜单搜索把它找出来、打开窗口，再选文件、选设备。用户想要的是：拿起文件，拖到屏幕角落，松手就发出去。

接收这边，用户自己的几台 Windows 电脑之间互相发文件时，不想每次点确认；但手机和别人发来的文件仍然要确认后才收。收到的文件，修改时间要改成收到的时间。

## 这是什么

一个 Windows 小程序（独立的 exe）。LocalSend 没有插件机制，所以它不是 LocalSend 的插件，而是和原版 LocalSend 并排运行的配套程序。

下文“本程序”指这个 exe，“原版”指官方 LocalSend。

**核心原则：原版不动。** 原版照常运行在托盘里，照常占用 53317 端口、照常被手机发现、照常接收手机和其他设备发来的文件并弹窗确认。本程序不改原版的端口和设置，不让它停下，也不写它的任何文件。本程序只做三件原版做不到的事：

1. 屏幕角落的拖放发送区；
2. 一条只给用户自己几台电脑用的专用接收通道，共享密码对就自动收；
3. 把原版收到的文件的修改时间改成收到的时间。

## 目标

### 一、发送：角落拖放

1. 平时屏幕上什么都不显示，不占位置，不拦截任何点击。
2. 用户从资源管理器、桌面或任何支持 Windows 拖放的地方拖着文件（一个或多个）靠近屏幕角落时，角落出现一个小发送区。默认右下角，位置在任务栏上方，不盖住任务栏和“显示桌面”按钮；设置里可以换成别的角。
3. 拖到发送区上不松手，旁边展开设备列表：当前在线、已发现的 LocalSend 设备，包括开着原版 App 的手机、其他电脑。不列出本机自己。列表要在发送区出现时立即可用，不能等扫描。
4. 在某个设备上松手：直接发送，不打开任何窗口。发送路线：
   - 对方电脑也装了本程序：走对方的专用端口，带上密码令牌，对方自动收。
   - 对方专用端口回复“密码不对”（401）：改走对方的 53317，交给对方的原版，对方会弹窗确认；本机通知用户“密码不一致，已改为普通发送”。
   - 其他设备（手机、只装原版的电脑）：走对方的 53317，按普通 LocalSend 流程发送。对方开了“需要 PIN”并返回 401 时，弹一个小输入框让用户输入对方的 PIN 再重试。
5. 在发送区本身上松手：把文件交给本机正在运行的原版，让原版窗口带着这些文件打开，用户在原版里挑设备或再加文件。原版从 1.15 起支持通过命令行参数传入初始文件（`localsend_app.exe <文件路径>...`），实现时要先验证原版已经在运行时这些参数能不能送到它手里。**我的决定**：如果送不到，就只把原版窗口调到前台，再弹通知提醒用户把文件拖进去；不做界面自动化，也不做本程序自己的选设备窗口。
6. 拖到别处松手：取消，发送区收起。
7. 发送结果（成功、失败、被对方拒绝）用 Windows 系统通知提示。

交互参考：对话里画过一张可以拖着试的示意图，右下角一个约 68px 的圆角方块（图标加“LocalSend”字样），悬停后左侧竖排弹出设备卡片（图标加设备名）。具体样式由实现者定。

### 二、发现设备，但不占原版的端口

- 本程序发送只需要主动连到对方，不需要监听 53317。
- 发现设备时，**不能让这台电脑在手机等设备上多出一个条目**。协议里的 `POST /register` 会让对方把发起者加进它的设备列表，所以本程序不能以自己的身份去 register。可行的做法（由实现者验证后选定）：
  - 和原版共享地监听组播 224.0.0.167:53317（地址复用，不独占），被动收集其他设备的公告；
  - 对局域网 IP 发 `GET /api/localsend/v2/info` 探测，这个接口只返回对方信息，不会把本机登记进去；
  - 如果非用 register 不可，就用原版自己的身份信息（通过 `http(s)://127.0.0.1:53317/api/localsend/v2/info` 读取原版的 `alias`、`fingerprint`、`port`、`protocol`），这样对方只会刷新原版那个条目，不会多出一个。
- 向手机等设备发送时，`prepare-upload` 里的 `info` 也用原版的身份信息，让对方看到的发送方就是这台电脑原本的名字。
- 设备是否装了本程序：探测对方 IP 上的专用端口，有本程序的回应就记下来。
- 设备列表在后台持续维护（组播随时更新，探测定期刷新，开始拖动时再补一次），保证发送区弹出时列表马上可用。

### 三、专用接收通道（用户自己几台电脑之间）

1. 本程序登录 Windows 后自动启动，没有窗口，只有托盘图标。用户已接受：不做开机未登录也能收的 Windows 服务；电脑开着但没人登录时，专用通道收不到文件（原版那一路看原版自己的设置）。
2. 监听一个固定的专用 TCP 端口，所有装本程序的电脑用同一个号码。默认值由实现者选一个不和 LocalSend 冲突的（比如 53319），设置里可改。这个端口**不做组播公告**，手机等设备不会发现它。
3. 通道用 HTTPS（自签证书），接口沿用 LocalSend 协议 v2 的 `prepare-upload`、`upload`、`cancel`，另加一个让发送方确认“这是本程序”的探测接口。这样发送代码两条路线可以共用。
4. 只接受带正确密码令牌的请求，不弹任何确认窗。没带令牌或令牌不对一律返回 401，由发送方改走对方原版（见“发送”第 4 条）。对连续失败的来源限流（429）。
5. 收到的文件：
   - 存进当前用户的“下载”文件夹（按 Windows 的已知文件夹取路径，不写死）；
   - 遇到同名文件自动改名为 `报告 (1).pdf`、`报告 (2).pdf`……，不覆盖；
   - 接收完成后把**修改时间**设为接收完成的时刻，忽略发送方带来的 `metadata.modified`；**创建时间不动**；
   - 弹一条系统通知，点击打开“下载”文件夹并选中该文件。

### 四、共享密码

- 每台装本程序的电脑在设置里填一次，以后不用再输。
- 本机保存时加密（建议 Windows DPAPI，按当前用户加密），不写明文。
- 密码本身不能出现在网络上。**我的决定**（实现者可以换成同等强度的方案）：发送方在 `prepare-upload` 的 `pin` 参数里放一个由密码派生的短时令牌，例如 `HMAC-SHA256(密码, "lsdz1|" + 接收方专用通道证书指纹 + "|" + 当前分钟数)` 截取后的编码；接收方用自己的指纹和自己存的密码计算，允许前后约 2 分钟的时钟误差。
- 发送方先确认专用通道的 TLS 证书 SHA-256 与探测时拿到的指纹一致，再发令牌。
- 令牌只发往专用端口，不发给原版或手机。

### 五、修正原版收到的文件的修改时间

手机和陌生设备发来的文件由原版接收、原版弹窗、原版保存（原版自己处理同名改名）。本程序在原版保存完成后，把这些文件的修改时间改成接收完成的时刻，创建时间不动。

- 本程序不能改原版的设置，只能读。**我的决定**：优先只读地读取原版的接收历史（原版把历史存在自己的配置文件里，实现者先查清位置和格式），发现新记录就按记录里的路径改修改时间。
- 用“接收完成时刻”而不是“本程序发现的时刻”；历史里有时间就用历史里的，没有就用文件最后一次写入完成的时刻。
- 只改原版刚收到的文件，不碰“下载”里的其他文件。
- 如果原版的历史读不到或不可靠：首次运行时提示用户在原版设置里把保存位置改成一个专用文件夹，本程序盯着那个文件夹，改完时间后把文件挪进“下载”（同名自动改名）。本程序自己不去改原版的设置。

### 六、设置、托盘和首次运行

托盘菜单：设置、打开“下载”文件夹、暂停专用通道接收、退出。

设置项：
- 共享密码
- 专用端口号（默认值见上，所有电脑要一致）
- 发送区所在的角
- 开机自启开关

首次运行：
- **用户决定（2026-10-19）**：每次启动检查一次，缺少时弹一次管理员确认，给本程序添加 Windows 防火墙入站规则，对“专用网络”和“公用网络”都生效（和原版 LocalSend 一样）。
- 不检查、也不修改网络类别。
- 检查原版是否在运行、是否开机自启；不满足时提示用户去原版设置里打开，本程序不改。

## 非目标

- 不做 Mac、Linux 版本，所有装本程序的电脑都是 Windows。
- 不改原版的端口、设置或文件，不停止原版，不和原版抢 53317。
- 不改手机端，手机继续用原版 LocalSend；手机发给电脑每次都要点确认。
- 不解决 iPhone 后台接收：iOS 规定 LocalSend 必须开在前台才能收，iPhone 只有在 App 打开时才出现在设备列表里。
- 不做未登录时的接收。
- 不做跨网段或互联网传输，只在同一局域网内。
- 第一版不做传输历史和传输管理界面。
- 不做原版的“网页分享”（反向下载）模式。
- 不做本程序自己的选设备窗口。

## 反目标（技术上能用但算失败）

- 原版因为本程序出问题：端口被占、发现不了设备、设置被改。
- 手机等设备上，这台电脑出现两个条目。
- 平时在角落挡住点击或占位置，尤其挡住任务栏和“显示桌面”。
- 陌生设备发来的文件没经确认就落进“下载”。
- 共享密码以明文出现在网络上，或明文存在磁盘上。
- 拖着文件到角落时发送区出现得慢、卡顿，手感不如直接用原版。
- 普通的鼠标拖动（拖窗口、框选）时频繁误弹发送区，打扰正常操作。
- 改动了文件内容，或者改动了修改时间以外的文件属性；改了不是刚收到的文件的时间。

## 约束

- 系统：Windows 11（用户这台是 10.0.26200）。
- 原版：装在 `C:\Program Files\LocalSend\`，当前 1.18.2，运行在托盘，占用 53317。
- 协议：兼容 LocalSend 协议 v2（文档 <https://github.com/localsend/protocol>）。关键点：默认端口 TCP/UDP 53317；组播地址 224.0.0.167:53317；设备公告字段 `alias`、`version`、`deviceModel`、`deviceType`、`fingerprint`、`port`、`protocol`、`download`、`announce`；`POST /api/localsend/v2/register` 会把发起者登记进对方列表；`GET /api/localsend/v2/info` 只返回信息；发送流程 `POST /api/localsend/v2/prepare-upload?pin=...`（401 表示需要或错误的 PIN，403 拒绝，409 对方正忙，429 请求过多）、`POST /api/localsend/v2/upload?sessionId=&fileId=&token=`、`POST /api/localsend/v2/cancel?sessionId=`；HTTPS 下 `fingerprint` 是 TLS 证书的 SHA-256。
- 要和原版 1.18.2（Windows）、iOS 和 Android 上的原版互通。
- 技术：C# / .NET，打包成一个 exe。这台机器装了 .NET 8 和 10 的运行时，但没有 SDK，开发前需要装 SDK。
- 位置：一个 git 仓库。目录名小写加连字符，不用空格和中文。

## 验收

1. 原版照常运行，本程序启动后原版的端口、设置都没变，原版照样能发现设备、收发文件。
2. 手机打开 LocalSend 后，设备列表里这台电脑只出现一次。
3. 从资源管理器拖一个文件到右下角，发送区立刻出现；悬停后看到 iPhone（App 开着）、安卓手机、另一台装本程序的电脑；松在 iPhone 上，iPhone 弹出接收请求，发送方显示的是这台电脑原来的名字，接受后收到文件。
4. 两台装本程序、密码相同的电脑互发：接收方没有弹窗，文件出现在“下载”，修改时间等于接收时间，创建时间不变，有系统通知。
5. 两台密码不同：发送方收到“密码不一致，已改为普通发送”的通知，接收方的原版弹窗确认。
6. 手机用原版 LocalSend 发给电脑：电脑上原版弹窗，接受后文件在“下载”里，修改时间等于接收时间。
7. “下载”里已有同名文件时，专用通道收到的新文件改名为 `xxx (1).ext`，旧文件不变。
8. 拖到发送区本身松手：原版窗口打开，文件已在待发送列表里（或者按降级方案：窗口到前台并弹通知）。
9. 拖窗口、框选等普通操作经过角落时，不出现误弹，或者偶尔出现但松手立即消失、不影响操作。
10. 重启电脑并登录后，本程序自动在托盘运行，不弹任何窗口。
11. 用抓包或日志确认共享密码没有以明文出现在网络请求里。

## 留给实现者

- UI 框架（WPF、WinForms 或 WinUI）、HTTPS 服务器实现、自签证书的生成和保存、设置文件的格式和位置、托盘和系统通知的实现、开机自启方式（注册表 Run 键或任务计划程序）。
- 怎样检测“正拖着文件靠近角落”而不放常驻窗口。一个可行思路：低级鼠标钩子监测按住左键移动到角落附近时，才在角落显示一个注册了拖放目标的置顶小窗口，Windows 的拖放循环会在光标移进它时触发 DragEnter。实现者验证后可以换成更好的办法。
- 设备发现的具体组合（见“二”），前提是不占原版端口、不让本机多出条目。
- 多显示器时角落怎么判定（我的建议：光标所在显示器的那个角）。
- 拖入文件夹：希望和原版一样支持（保持相对路径），先查清原版发送和接收文件夹时 `fileName` 的格式再照做。
- 专用通道同时有多个发送方时排队还是并行。
- 专用端口的默认号码。
