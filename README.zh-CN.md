# LocalSend Dropzone

> **非官方（Unofficial）。** LocalSend Dropzone 是 [LocalSend](https://localsend.org) 的一个非官方配套小工具，与 LocalSend 项目没有关联，也未获其认可或背书。

语言：[English](README.md) | 简体中文

Windows 小程序，和官方 LocalSend 并排运行。它不替代原版，也不改原版的端口、设置或文件。

## 这是什么

- **和原版并排运行。** 原版照常在托盘里运行，照常占用 53317 端口，照常被手机发现，照常接收手机发来的文件并弹窗确认。
- **角落拖放发送。** 拿着文件拖到屏幕角落（默认右下角），出现发送区，悬停后选设备，松手即发，不用先打开任何窗口。
- **自己几台电脑之间免确认接收。** 每台电脑填同一个共享密码。装了本程序的电脑之间互发，接收方不弹窗，文件直接存进“下载”文件夹。
- **修改时间。** 原版收到的文件，修改时间改成接收完成的时刻。创建时间不变。

## 在你的电脑和网络上做什么（What it does on your machine and network）

- **读取原版的设置文件。** 只读取原版的 `%APPDATA%\LocalSend\settings.json`，从不写入，只用其中的别名、端口、接收历史和“保存到历史”开关。文件里保存的 TLS 私钥（`flutter.ls_security_context`）不会被提取、记录或发送；程序把文件读进内存只是为了找出这几项，随后清零缓冲区。
- **以原版的身份在局域网上公告和登记。** 只在原版运行时进行，使用原版的别名和证书指纹：在每个 IPv4 网卡上每 30 秒组播一次公告（224.0.0.167，UDP 53317）；每 45 秒，向最近 7 天见过的设备和本机所在的小网段（/24 及更小）发送登记请求。原版没在运行时，停止公告和登记，免得手机列出一台收不了文件的电脑。
- **监听 TCP 53319，共享 UDP 53317。** 在 TCP 53319 上监听（专用端口，可在设置里改），供装了本程序的电脑之间互传；与原版共享 UDP 53317（地址复用，不独占，不抢走原版的端口）。
- **Windows 防火墙。** 每次启动先检查入站规则，缺失时添加允许规则，覆盖专用端口和 UDP 53317，专用网络和公用网络都生效。添加规则需要管理员确认（UAC），提示框里的程序是 LocalSendDropzone。程序只管理自己名下的规则，不删除其他规则。
- **修改文件时间。** 原版刚收到的文件，程序把修改时间改成接收完成的时刻（依据原版的接收历史）。只改修改时间；收到后你改过的文件不动。
- **开机自启。** 默认开启：在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下添加一个当前用户的启动项，可在设置中关闭。
- **本地数据。** 全部写在 `%LOCALAPPDATA%\localsend-dropzone\` 下（见下文“数据和日志”）。共享密码用 Windows DPAPI 按当前用户加密。

## 安装

1. 把 `publish\LocalSendDropzone.exe` 放到一个固定位置（例如 `%USERPROFILE%\Apps\localsend-dropzone\publish\`），然后运行。
   防火墙规则和开机自启都记着 exe 的路径，所以换了位置要重新运行一次。
2. 每次启动都会先检查防火墙入站规则，规则就绪后才开始监听端口。第一次运行，或 exe 换了位置时，可能弹一次管理员确认（UAC，提示框里的程序是 LocalSendDropzone 本身）。它用来添加防火墙入站规则，允许专用端口和 UDP 53317，专用网络和公用网络都生效，和原版 LocalSend 一样。如果拒绝，其他电脑可能连不上，程序会弹一条通知。
   - 如果出现 Windows 自己的防火墙对话框（“Windows 安全中心警报”），把“专用网络”和“公用网络”都勾上，再点“允许访问”。
   - 如果 Windows 里已经有阻止本程序的规则（比如那个对话框没勾选就关掉了），添加允许规则也没用，程序会通知你到“允许应用通过防火墙”里放行 LocalSendDropzone。程序不会删除任何别的防火墙规则。
3. 在托盘图标上打开“设置”，每台电脑都填：
   - **共享密码**：至少 12 个字符，所有电脑填同一个。保存时用 Windows DPAPI 按当前用户加密，文件里没有明文。
   - **专用端口**：默认 53319，所有电脑要一致，不能是 53317，也不能是原版设置里用的端口。
   - 发送区位置、开机自启（默认开）也在这里设置。
4. 原版 LocalSend 要保持运行，并设成开机启动。本程序每次启动都会检查这两项（随 Windows 启动时，先给原版 2 分钟时间启动），不满足时只弹通知，不会替你改原版的设置；开机启动的提醒只在第一次发现没开、或从开着变成关掉时弹一次。运行中原版退出了，也会弹一次通知。原版设置里关掉了“保存到历史”时，也会提示一次。

## 使用

- **发送**：把文件（一个或多个）拖到屏幕角落，发送区出现。悬停在上面，设备列表朝屏幕内侧展开（不含本机）。松手在某个设备上，直接发送，结果用 Windows 通知提示。
  - 对方是装了本程序的电脑：走专用端口，对方自动收。
  - 对方是手机或只装原版的电脑：走原版的普通流程，对方会弹窗确认。如果对方要求 PIN，会弹一个小框让你输入。
  - 对方的专用端口返回“密码不对”：改为普通发送，发送方会收到“密码不一致，已改为普通发送”的通知，对方的原版会弹窗。
- **接收**：专用通道收到文件后，每次发送只弹一条通知：一个文件时显示文件名，点通知在资源管理器里选中它；多个文件时显示“已收到 N 个文件”，点通知打开装着它们的文件夹。
- **交给原版**：松手在发送区本身上，文件交给正在运行的原版窗口，在原版里选设备。如果交接失败，原版窗口会调到前台，并提示你把文件拖进去。
- **取消**：拖到别处松手，发送区收起。
- **托盘菜单**：
  - 设置
  - 打开“下载”文件夹
  - 暂停接收：只暂停专用通道的接收，原版不受影响。暂停不会被记住，退出或重启后恢复接收。
  - 退出

## 已知限制

- **iPhone**：只有 LocalSend 开在前台时，iPhone 才能收文件，也才出现在设备列表里。
- **手机发给电脑**：每次都要在电脑上点确认。
- **没登录的电脑**：电脑开着但没人登录时，专用通道收不到文件。原版那一路不受影响，仍按原版自己的设置工作。
- **修改时间**：依赖原版的“保存到历史”。在原版里关掉它，修改时间就不会修正。历史只保留最近 30 条，一次收很多文件时，较早的条目可能来不及处理。收到后被你改过的文件不会动。
- **网络**：只在同一局域网内使用，不支持跨网段或互联网。
- **系统**：只支持 Windows。
- **界面语言**：托盘菜单、设置窗口和通知目前是中文。

## 数据和日志

数据目录是 `%LOCALAPPDATA%\localsend-dropzone\`：

- `settings.json`：设置。共享密码只以 DPAPI 加密的形式保存。
- `cert.bin`：专用通道的自签名证书，同样加密保存。
- `seen-history.json`、`known-hosts.json`：程序内部记录。
- `logs\app.log`：日志，每天滚动，保留 14 天。日志里不记共享密码，PIN 和令牌的值也会被打码。

本程序只读取原版的 `%APPDATA%\LocalSend\settings.json`，从不写入。

## 开发

- 需要 .NET 10 SDK。
- 代码结构：`src/dropzone-core`（核心库）、`src/dropzone-app`（托盘程序）、`tests/dropzone-core-tests`（测试）。
- 设计和实测结论（中文）见 `docs/superpowers/specs/` 和 `docs/notes/`。
- 运行测试（在仓库根目录）：

  ```
  dotnet test
  ```

- 发布：

  ```
  dotnet publish src/dropzone-app -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
  ```

  输出是 `publish\LocalSendDropzone.exe`。`publish\` 已在 `.gitignore` 中。
