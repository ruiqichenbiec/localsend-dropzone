# LocalSend Dropzone

LocalSend Dropzone是一个用于扩展和增强LocalSend 桌面App的应用，提供了一个通过拖放触发的LocalSend发送方案。它是一个 Windows 托盘程序，与官方 [LocalSend](https://localsend.org) 并行运行，不替代、也不修改官方 App。设备发现和文件传输遵循 LocalSend 协议，因此手机及其他设备不需要安装任何额外软件。

> 非官方工具，与 LocalSend 项目没有关联，也未获其认可。运行 Dropzone 需要同时安装官方 LocalSend。

语言：[English](README.md) | 简体中文

## 功能

Dropzone 提供三项功能。

### 1. 拖放发送

Dropzone 通过全局鼠标钩子识别拖动操作。拖动中的光标进入屏幕角落（默认右下角，位于任务栏上方）的触发区域时，角落出现**发送区**；光标停在发送区上时，旁边展开**设备列表**，列出局域网中已发现的设备（不含本机）。

```
                          ┌──────────────┐
                          │ Pixel 8      │   ← 设备列表
                          │ 我的笔记本   │  ┌───────────┐
                          │ 办公室电脑   │  │ LocalSend │  ← 发送区
                          └──────────────┘  └───────────┘
═══════════════════════════════════════════════════════════ 任务栏
```

松开鼠标的位置决定操作：

| 松开位置 | 结果 |
|---|---|
| 设备列表中的某个设备 | 直接发送给该设备 |
| 发送区本身 | 打开官方 LocalSend 窗口，拖动的文件已被选中 |
| 其他任何位置 | 取消 |

没有拖动操作时，屏幕上不显示任何内容，也不拦截鼠标点击。发送结果（已发送、被拒绝、失败）以 Windows 通知的形式显示。

### 2. 自有电脑之间免确认接收

安装了 Dropzone 并设置了相同**共享密码**的 Windows 电脑之间，接收方不弹出确认窗口，文件直接写入“下载”文件夹。

这一功能通过一条独立于官方 LocalSend 的**专用通道**实现：每台电脑上的 Dropzone 在专用端口（默认 TCP 53319）上运行一个 HTTPS 接收服务。每次传输都附带一个由共享密码派生的校验码，接收方验证通过才接收文件。校验码在 ±2 分钟内有效，密码本身不经过网络。

校验未通过时（例如两台电脑的密码不同），发送方自动改用 LocalSend 的普通流程，由接收方的官方 App 弹窗确认。

### 3. 接收时间修正

官方 LocalSend 收到的文件，其“修改日期”被设为接收完成的时刻，因此按日期排序时，新收到的文件排在最前。创建日期和文件内容保持不变；收到后被修改过的文件不作处理。

接收完成的时刻取自官方 LocalSend 的接收历史，因此这一功能依赖官方 App 的“保存到历史”选项（默认开启）。

## 与官方 LocalSend 的分工

| 传输方向 | 发送端 | 接收端 | 是否需要确认 |
|---|---|---|---|
| 电脑 → 手机 | Dropzone | 手机上的 LocalSend | 手机上确认 |
| 电脑 → 只装有官方 App 的电脑 | Dropzone | 对方的官方 LocalSend | 对方确认 |
| 电脑 → 装有 Dropzone 且密码相同的电脑 | Dropzone | 对方的 Dropzone | 不需要 |
| 手机 → 电脑 | 手机上的 LocalSend | 本机的官方 LocalSend | 电脑上确认 |

Dropzone 对外使用本机官方 LocalSend 的名称和证书指纹，因此在其他设备上，这台电脑只显示为一个条目。官方 LocalSend 未运行时，Dropzone 停止对外公告，避免其他设备列出一台无法接收文件的电脑。

## 运行要求

- Windows 11（64 位）。
- 官方 LocalSend 已安装并保持运行。从手机发往电脑的文件由官方 App 接收，因此官方 App 应设置为开机启动并常驻托盘。
- 所有设备位于同一局域网。

## 安装与配置

1. **获取程序。** 从 [Releases](https://github.com/ruiqichenbiec/localsend-dropzone/releases) 下载 `LocalSendDropzone.exe`，或从源码编译（见[从源码编译](#从源码编译)）。程序为单个可执行文件，自带 .NET 运行时，无需安装。程序没有代码签名，首次运行时 Windows SmartScreen 可能显示警告，选择“更多信息 → 仍要运行”即可。
2. **放置位置。** 程序应放在固定的文件夹中运行。防火墙规则和开机启动项都记录程序所在路径；移动程序后，在新位置运行一次即可更新。
3. **防火墙。** 专用通道和设备发现需要接受来自局域网的连接，因此 Dropzone 每次启动时检查 Windows 防火墙规则。首次运行时可能出现两种提示：
   - Windows 的“Windows 安全中心警报”：需同时勾选“专用网络”和“公用网络”并允许访问；
   - Dropzone 请求管理员权限（UAC）以添加自己的防火墙规则：同意后规则对专用和公用网络都生效。
4. **共享密码。** 在托盘菜单的“设置”中填写，至少 12 个字符。所有需要互相免确认传输的电脑必须使用同一密码和同一专用端口（默认 53319）。
5. **其他电脑。** 在每台需要免确认传输的 Windows 电脑上重复以上步骤。

Dropzone 默认随 Windows 启动，可在“设置”中关闭。

## 操作参考

| 操作 | 方法 |
|---|---|
| 发送文件或文件夹 | 拖向屏幕角落，停在发送区上，在设备上松开 |
| 在官方 LocalSend 窗口中选择设备 | 在发送区本身上松开 |
| 发送到 iPhone | 先在 iPhone 上打开 LocalSend；iOS 只允许 LocalSend 在前台时接收 |
| 输入接收方要求的 PIN | 发送时 Dropzone 弹出输入框 |
| 暂停专用通道的接收 | 托盘菜单 →“暂停接收”；重启后自动恢复，不影响官方 LocalSend |
| 更改发送区所在的屏幕角落 | 托盘菜单 →“设置” |
| 打开“下载”文件夹 | 托盘菜单 →“打开‘下载’文件夹” |

专用通道收到文件后，每次传输显示一条通知：单个文件时显示文件名，点击后在资源管理器中选中该文件；多个文件时显示文件数量，点击后打开所在文件夹。同名文件会被重命名为“名称 (1).扩展名”，不会覆盖已有文件。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 设备列表中缺少某台设备 | 该设备未打开 LocalSend，或不在同一网络 | 在该设备上打开 LocalSend 并确认网络；开始拖动时列表会刷新 |
| 手机上看不到这台电脑 | 本机的官方 LocalSend 未运行 | 启动官方 LocalSend；Dropzone 会就此显示通知 |
| 自己的另一台电脑仍要求确认 | 对方未运行 Dropzone、密码不同，或两台电脑时钟相差超过 2 分钟 | 检查对方的 Dropzone 和密码；密码不同时会显示“密码不一致，已改为普通发送” |
| 通知“Windows 防火墙阻止了本程序……” | Windows 中存在阻止 Dropzone 的规则，通常因防火墙对话框未被允许就关闭而产生；阻止规则优先于允许规则 | 在 控制面板 → Windows Defender 防火墙 →“允许应用通过防火墙”中，为 LocalSendDropzone 勾选专用和公用网络 |
| 接收时间没有被修正 | 官方 LocalSend 关闭了“保存到历史” | 在官方 App 中重新开启；Dropzone 会就此提示一次 |

## 限制

- 仅在同一局域网内工作，不支持跨网络或经由互联网的传输。
- 从手机发往电脑的传输始终需要在电脑上确认；免确认仅适用于装有 Dropzone 的电脑之间。
- 接收方电脑开机但无人登录时，专用通道不接收文件。
- 官方 LocalSend 的接收历史只保留最近 30 条，一次接收大量文件时，较早的条目可能在修正之前已被移出。
- 托盘菜单、设置窗口和通知目前只有中文界面。

## 对系统和网络的影响

Dropzone 不修改官方 LocalSend 的设置、端口和文件。它对系统和网络的全部影响如下：

- **读取官方 App 的设置文件** `%APPDATA%\LocalSend\settings.json`，只使用其中的名称、端口、接收历史和“保存到历史”选项；从不写入该文件，也从不提取、记录或发送其中保存的私钥。
- **局域网公告与登记：** 官方 LocalSend 运行期间，每 30 秒以官方 App 的身份发送一次组播公告（UDP 53317），并定期联系最近 7 天内见过的设备。
- **端口：** 监听 TCP 53319（专用端口，可修改）；与官方 App 共用 UDP 53317，不独占。
- **防火墙：** 经用户同意后，为本程序添加入站允许规则（专用和公用网络）；只管理自己名下的规则，不删除其他规则。
- **文件：** 只修改官方 LocalSend 刚收到的文件的“修改日期”；专用通道收到的文件写入“下载”文件夹。
- **开机启动：** 在当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下添加启动项。
- **本地数据：** 全部位于 `%LOCALAPPDATA%\localsend-dropzone\`，包括设置（共享密码经 Windows DPAPI 加密）、专用通道的证书、最近见过的设备列表和日志（`logs\app.log`，保留 14 天，不记录密码和校验码）。

## 从源码编译

需要 .NET 10 SDK。

```
dotnet test
dotnet publish src/dropzone-app -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

输出为 `publish\LocalSendDropzone.exe`。

代码结构：

| 目录 | 内容 |
|---|---|
| `src/dropzone-core` | 核心逻辑：协议、发送、专用通道接收、设备发现、时间修正 |
| `src/dropzone-app` | 托盘程序、设置窗口、发送区 |
| `tests/dropzone-core-tests` | 核心逻辑的测试 |
| `docs/` | 设计文档和 LocalSend 协议实测记录 |
